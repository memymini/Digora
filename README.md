# Digora

온라인 투표 및 여론 조사 플랫폼

## 1. 프로젝트 개요 (Overview)

Digora는 사용자들이 다양한 주제에 대해 투표하고, 실시간으로 결과를 확인할 수 있는 웹 플랫폼이며, 모바일 뷰 또한 제공합니다.

### 주요 기능

- **투표 참여**: 진행 중인 투표에 참여하고 의견 표출
- **실시간 통계**: 연령별, 성별, 시간대별 투표 결과 시각화
- **댓글 시스템**: 투표에 대한 의견, 대댓글 공유 및 좋아요 기능
- **관리자 대시보드**: 투표 생성/관리, 신고 댓글 처리, 일일 통계

### 페이지 구성

| 페이지    | 경로           | 설명                   |
| --------- | -------------- | ---------------------- |
| 홈        | `/`            | 메인 투표 및 투표 목록 |
| 투표 상세 | `/vote/[id]`   | 투표 참여 및 댓글      |
| 결과 분석 | `/result/[id]` | 투표 통계 시각화       |
| 관리자    | `/admin`       | 투표/신고 관리         |
| 로그인    | `/login`       | 카카오 OAuth 로그인    |

## 2. 기술 스택 및 선정 이유 (Tech Stack & Rationale)

### Frontend

| 기술            | 버전 | 선정 이유                            |
| --------------- | ---- | ------------------------------------ |
| **Next.js**     | 15.5 | App Router, RSC 지원, SSR/SSG 최적화 |
| **TailwindCSS** | 4.1  | 빠른 스타일링, 일관된 디자인 시스템  |

### Backend & Database

| 기술              | 선정 이유                                      |
| ----------------- | ---------------------------------------------- |
| **Supabase**      | PostgreSQL + Auth + Realtime, 빠른 개발 |
| **Supabase Auth** | 카카오 OAuth 간편 연동, Row Level Security     |

### 상태 관리 & 데이터 페칭

| 기술               | 선정 이유                                    |
| ------------------ | -------------------------------------------- |
| **TanStack Query** | 서버 상태 캐싱, 자동 리페칭, 낙관적 업데이트 |
| **Zustand**        | 클라이언트 상태 관리, 간결한 API             |

### 폼 & 유효성 검사

| 기술                | 선정 이유                       |
| ------------------- | ------------------------------- |
| **React Hook Form** | 비제어 컴포넌트 기반, 높은 성능 |

### 시각화

| 기술         | 선정 이유                           |
| ------------ | ----------------------------------- |
| **Recharts** | React 친화적, 다양한 차트 타입 지원 |

### 테스트

| 기술           | 선정 이유                  |
| -------------- | -------------------------- |
| **Vitest**     | Vite 기반 빠른 단위 테스트 |
| **Playwright** | 크로스 브라우저 E2E 테스트 |

## 3. 프로젝트 아키텍처 (Architecture)

### 디렉토리 구조

```
src/
├── app/                    # Next.js App Router
│   ├── api/               # API Routes
│   │   ├── auth/         # 인증 (callback, logout)
│   │   ├── votes/        # 투표 API
│   │   ├── comments/     # 댓글 API
│   │   └── admin/        # 관리자 API
│   ├── vote/[id]/        # 투표 상세 페이지
│   ├── result/[id]/      # 결과 분석 페이지
│   ├── admin/            # 관리자 페이지
│   └── page.tsx          # 홈 페이지
│
├── components/            # UI 컴포넌트
│   ├── ui/               # 기본 UI (Button, Card, Badge)
│   ├── common/           # 공통 (Header, Footer)
│   ├── home/             # 홈 페이지용
│   ├── vote/             # 투표 페이지용
│   ├── result/           # 결과 페이지용 (차트)
│   └── admin/            # 관리자용
│
├── services/              # 비즈니스 로직
├── repositories/          # 데이터 접근 계층
├── hooks/                 # 커스텀 훅 (mutations, queries)
├── types/                 # 타입 정의
│   ├── domain.ts         # 도메인 모델
│   ├── request.ts        # API 요청 타입
│   ├── response.ts       # API 응답 타입
│   └── enums.ts          # 상수 및 열거형
├── utils/                 # 유틸리티 함수
│   ├── api.ts            # API 응답 헬퍼
│   └── mappers.ts        # 데이터 변환
└── lib/                   # 외부 라이브러리 설정
    └── supabase/         # Supabase 클라이언트
```

### 레이어 아키텍처

```
┌─────────────────────────────────────────────────┐
│                    Pages                         │
│              (app/**/page.tsx)                   │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│                 Components                       │
│           (Presentational Layer)                 │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│              Hooks (useQuery/useMutation)        │
│              + API Routes (/api/**)              │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│                  Services                        │
│             (Business Logic)                     │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│                Repositories                      │
│              (Data Access)                       │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│                  Supabase                        │
│           (PostgreSQL + Auth)                    │
└─────────────────────────────────────────────────┘
```

### 데이터 흐름

```
[Client] ──▶ [API Route] ──▶ [Service] ──▶ [Repository] ──▶ [Supabase]
                │                              │
                │                              ▼
                │                         [DB Query]
                │                              │
                ◀──────────── [Response] ◀─────┘
```

### 인증 흐름

```
[사용자] ──▶ [카카오 로그인] ──▶ [Supabase Auth]
                                      │
                                      ▼
                              [/api/auth/callback]
                                      │
                                      ▼
                              [프로필 생성/조회]
                                      │
                                      ▼
                                [홈으로 리다이렉트]
```
